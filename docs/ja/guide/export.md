# エクスポートと振り返り

摊盒の書き出しは次の種類に分かれていて、用途はまったく異なります。

- **売上集計**（CSV / Excel）：「何が売れたか」に答えるもの。イベント後の振り返りや成績表に
- **精算書**（`settlement_<イベント名>.xlsx`）：「お金をどう分けるか」に答えるもの。所有サークル（荷主）への分配と入金照合に
- **商品パック `.boothpack`**：商品マスタの移行用。イベントや注文のデータは一切含みません
- **過去データ（v1）**：v1.1 からアップグレードした方は、旧バージョンのイベントと注文を Excel に書き出せます

以下、それぞれの入口・形式・用途を説明します。

:::warning ⚠️ `.boothpack` は完全バックアップではありません
`.boothpack` に入っているのは**商品マスタ（名前・価格・番号・画像）だけ**で、**イベント・注文・売上の記録は含まれません**。
「書き出したからこのイベントのバックアップも取れた」と思っていると、あとで売上データを探したときに入っていないことに気づくことになります。
イベントのデータは Excel（売上集計と精算書）に書き出せますが、**書き出した表はアプリに取り込み直せません**。端末を替えたりデータを消去したりする前に、端末上のデータベースファイルを別途バックアップしてください。
:::

## 売上集計：CSV / Excel

イベント後の振り返りや、サークル代表に成績表を渡して分配を確認してもらうときに使います。

**入口**：サイドバーの「イベント」（画面表示「展会」）→ 対象のイベントに入る →「当日 · 統計」（画面表示「现场 · 统计」）。売上データがあると、ページ右上に 2 つのボタンが出ます。

- **CSV ダウンロード**（画面表示「下载 CSV」）：プレーンテキストの表で、項目は「頒布物番号・頒布物名・単価・販売数・売上」です。
  Excel / Feishu / Numbers に取り込んで加工したり、チャットに貼って成績を共有したりするのに向いています。
- **Excel レポートをダウンロード**（画面表示「下载 Excel 报告」）：`.xlsx` 形式で、イベント名・作成日時・表の書式が付いています。そのまま印刷したり
  サークル代表に送ったりでき、レイアウトを整え直す必要はありません。

どちらもデータの出どころは同じ（現在の絞り込み条件での売上集計）で、違いはファイル形式と書式の有無だけです。
ページ上部で頒布物の絞り込みや期間を設定している場合、書き出す内容もその絞り込み結果に従います。

## 精算書：`settlement_<イベント名>.xlsx`

売上集計が答えるのは「**何が売れたか**」、精算書が答えるのは「**お金をどう分けるか**」です。所有サークルごとの取り分、誰にいくら送金すべきか、支払い方法ごとの帳簿額と実際の差額がわかります。**委託販売の分配はこちらで見ます。**

**入口**：サイドバーの「イベント」→ 対象のイベントに入る →「撤収 · 精算」（画面表示「收摊 · 结算」）で、精算書右上の「Excel 出力」（画面表示「导出 Excel」）。売り子も売り子画面の「撤収」（画面表示「收摊」）タブで同じ精算書を見て書き出せます。精算書が完全になるのは、撤収ウィザード（注文の確認／棚卸し／持ち帰り／精算）を最後まで終えてからです。最初のステップでは**未確定（pending）の注文を 1 件ずつ完了またはキャンセルしておく**必要があり、そうしないとウィザードは最初のステップで止まります。棚卸しをしなかったイベントでは、表の見出しに「棚卸し未実施、残数は帳簿上の推定値」とはっきり表示されます。

<p style="text-align: center;"><img src="/images/v1.2/admin-settlement.png" alt="精算書の画面" style="width: 100%; border-radius: 8px; border: 1px solid var(--vp-c-divider);"></p>

1 つの `settlement_<イベント名>.xlsx` には 4 つのシートがあります。

| シート | 中身 | サークルが見るべき列 |
| --- | --- | --- |
| **精算サマリー**（「结算汇总」） | 所有サークルごとの商品定価、セット値引き、手動値引き、純額、返品による留保、自腹の贈呈品、立替、調整、そして最後の「送金すべき額」。その下には支払い方法ごとの帳簿額／実際／差額 | 「**送金すべき額**」（「我应转给」）。帳簿から計算した送金すべき金額です。立替と調整は 1 件ずつ名目が並んでいるので、わからない項目はここで確認します |
| **所有サークル明細**（「货主明细」） | 所有サークル × 商品ごとに、持ち込み／販売／贈呈／廃棄／差異／持ち帰り／会場在庫と、その行の定価／値引き／純額 | 「**純額**」（「净额」）。その商品の成約価格（セット値引きと返品を差し引き済み）で、サークルの会計はこの列で記帳します |
| **帳簿の記録**（「账本流水」） | 各 journal（仕訳）の時刻・種類・注文番号・摘要と、その仕訳のモノ側とお金側の記録 | 「このお金がどう記帳されたか」を調べたいときに見ます。1 つの journal が、それ以上分けられない 1 回の記帳です |
| **注文明細**（「订单明细」） | 注文ごと・行ごとの商品、セット、数量、単価、所有サークルの取り分、お客様の実際の支払額、返品済み数 | 特定の注文を照合するときは「**お客様の実際の支払額**」（「顾客实付」）と「**返品済み数**」（「已退件数」）を見ます |

:::warning ⚠️ 精算書の「送金すべき額」は「送金済み」ではありません
これは帳簿から計算した送金すべき金額です。**システムには入金を 1 件たりとも照合する手段がありません**。決済 API にはつながっておらず、「実際の手取り」も売り子が自分で数えて入力したものです。送金したら、控えは自分で保管しておいてください。

また、精算書は凍結後の追加入力（立替／精算調整／入金照合）に応じて更新されます。書き出す前に表の見出しの「最終更新」（画面表示「最后更新于」）を確認し、手元のものが最新かどうか確かめてください。
:::

## 商品パック：`.boothpack`

**端末の買い替え**や**複数人で分担して出展する**ときに商品マスタを移すためのもので、新しい端末で商品を 1 つずつ登録し直す手間を省けます。

**入口**：サイドバーの「商品マスタ」（画面表示「商品库」）ページを下にスクロールすると、「商品データパック（.boothpack）」（画面表示「商品数据包（.boothpack）」）パネルがあります。

- **.boothpack を書き出す**（画面表示「导出 .boothpack」）：現在のすべての商品の番号・名前・価格・カテゴリ・タグ・商用バーコード・所有サークルに加え、
  商品プレビュー画像と AI 認識用の参照画像をまとめて 1 つの `.boothpack` ファイル（中身は zip）にします。
- **.boothpack を取り込む**（画面表示「导入 .boothpack」）：`.boothpack` ファイルをパネルにドラッグするか、取り込みボタンを押してファイルを選びます。

**よくある使い方**：

- 自分のパソコンでこのイベントの商品をすべて登録済みで、当日はタブレットで会計する場合。
  書き出したファイルをタブレットに送って取り込めば、タブレットで打ち直す必要はありません。
- 売り子を仲間に任せる場合。`.boothpack` を送って取り込んでもらえば、
  相手の商品データがこちらと同じになります。

:::tip 取り込むと同じ番号の商品は上書きされます
`.boothpack` を取り込むとき、取り込み先の端末に同じ商品番号の商品がすでにあると、取り込んだデータで上書きされます。
うっかり上書きしないよう、取り込む前に現在のデータを書き出してバックアップしておくことをおすすめします。
:::

## 過去データ（v1）

v1.2 では帳簿が新しくなり、旧バージョンのイベントと注文は移行されず、バックアップファイル `sale_system.db.v1-backup` にそのまま残されています。

**入口**：アップグレード後に初めて管理画面にログインしたときに出るダイアログ、またはいつでも「**設定 → 過去データ（v1）**」（画面表示「设置 → 历史数据（v1）」）の「**旧データを Excel に書き出す**」（画面表示「导出旧数据为 Excel」）から。
書き出されるファイルは `legacy_v1_export.xlsx` で、「イベント」「注文」「注文明細」（「展会」「订单」「订单明细」）の 3 シートに、旧バージョンのすべてのイベントと注文が入っています。

旧データのない端末（新規インストール）では、この項目は表示されません。詳しくは [v1.1 から v1.2 へのアップグレード](./upgrade-v1.2) を参照してください。
